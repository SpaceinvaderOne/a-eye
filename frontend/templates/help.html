Processing Context

How the Reprocess with Context feature feeds extra hints into the vision model — what it does, when to use it, and where it bites.

What it is Flow Entry points What changes in the prompt Good context Weak context Gotchas TL;DR

What context actually is

Context is a freeform string (up to 500 characters) attached to an image before it runs through the vision pipeline. The model sees it as plain-English background information inside its prompt, alongside the photo's own EXIF metadata.

It is stored per-image in the images.processing_context SQLite column. If you reprocess the same image later with no new context, the stored value is reused.

The flow

user text ──► images.processing_context ──► worker ──► pipeline.process_image()
                                                                │
                                                                ▼
                                             prompts.render_vision_prompt()
                                                                │
                                                                ▼
                                                  Ollama vision model call

The context never ends up in filenames, descriptions, or tags directly. It only shapes what the model says about the photo. After reprocessing, the original processing_context value is left intact on the row so you can see what guided the result.

Entry points

Dashboard

Scan with Context

Kicks off a full scan and attaches the typed context to every newly-discovered image. Images already in the DB are untouched.

Image Modal

Reprocess

Single-image reprocess. The modal pre-fills with the last used context so you can tweak it or clear it.

Review / Queue

Bulk Reprocess

Same modal, same behaviour — context is stamped onto every selected image before they re-enter the worker queue.

Search

Reprocess Selected

Use search to narrow down a set (e.g. "dog") then reprocess the whole result with targeted context like "The grey husky is Jax".

What the model actually sees

Two things change in the prompt when context is present:

  1. A context block is injected into the prompt template just before the instructions, using the DEFAULT_CONTEXT_TEMPLATE. The model is told this is human-supplied background, not something it inferred from the image.
  2. The visible_rule swaps. Without context, the rule says "only describe what is clearly visible". With context, the rule relaxes slightly so the model may incorporate plausibly-related facts from the context when they clearly match what it sees.

The rest of the template — tags, quality step, format instructions, single-line DESCRIPTION contract — is unchanged. So a bad context will not corrupt filename parsing, only accuracy.

Context that helps

  • Named subjects. "The grey husky is Jax; the tabby cat is Pepper."
  • Event labels. "Holiday to Crete, July 2021."
  • Proper nouns the model can't infer. Street names, venue names, pet names.
  • Disambiguation hints. "These are all from the same kitchen renovation."
  • Language of the region. "Signs are in Japanese; prefer romaji in descriptions."

Context that wastes tokens

  • Descriptions the model will derive anyway. "A photo of a beach at sunset."
  • Instructions to the model. "Be more descriptive." — use the Prompt editor in Settings for that.
  • Information that contradicts the image. The model may either ignore it or hallucinate to reconcile.
  • Very long narratives. Over ~200 characters, the signal-to-noise ratio drops.

Gotchas

Known footgun

"Keep Existing Context" does not clear anything. Clicking it tells the server to skip updating the context field, so the previously stored value is still attached to the image when the worker picks it up. To actually run without context, use the new Clear Context button.

  • Scan with Context only tags new files. Existing rows already in the database are not updated — use Reprocess on those instead.
  • Context persists across reprocesses. The value in processing_context stays until you explicitly overwrite or clear it.
  • Context does not survive a rename. Once a file is applied, the context row stays but the description it produced is what gets written to EXIF/XMP — the raw context string is not embedded anywhere on disk.
  • Two separate DBs. Context set in the main library is invisible to the workspace and vice versa.
  • Length limit is 500 characters, enforced both in the UI and the route handler. Longer input is truncated silently.
  • It cannot override the vision prompt. If the model is refusing to describe something, tuning the default prompt in Settings will do more than stuffing the refusal workaround into context.

TL;DR

01

Use context to name things the model can't know — people, pets, places, events.

02

Keep it short and factual. ~200 characters or less.

03

To run a clean reprocess, use Clear Context, not Keep Existing.

04

Tune the system prompt in Settings for style; use context for specific facts.
